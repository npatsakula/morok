## Implemented

- PROGRAM remains the public compiler/runtime boundary and `ExecutionPlan` remains the owner of resolved call buffers.
- `ProgramInfo.globals` ordering is preserved by plan preparation; buffer GETADDR is resolved on the host after allocation through `Buffer::device_address`.
- C-like kernargs use one shared implementation: 64-bit resolved globals followed by positional 32-bit index vars.
- Backend-neutral ordered HCQ commands cover waits, barriers, compute, copy, timestamps, and stores.
- Deterministic null HCQ validates timeline waits and records exact command order.
- AMD AQL compute packets lower from the backend-neutral compute command.
- AMD per-call and graph kernarg writes share the canonical packer.
- AMD packet tests validate all dispatch fields and the barrier bit without executing hardware.
- AMD per-call program execution now packs kernargs once, constructs one neutral `MemoryBarrier -> Compute` submission for either PM4 or AQL, and routes both targets through queue lowering. Both paths finalize through monotonic wait/timestamp/store timelines; AQL carries its PM4 controls in barriered vendor IB packets and leaves kernel completion unset. Owner-local synchronous/asynchronous completion handling remains unchanged.
- Mock and packet tests prove PM4 and AQL consume the same ordered neutral compute intent. The obsolete direct native-AQL program helper/probe was removed.
- AMD lowers complete ordered compute submissions to PM4 and copy submissions to SDMA. PM4 covers dependency waits, HDP/full acquire barriers, raw dispatch, ordered timestamps, cache-flushing 64-bit stores/finalizers, and one-doorbell publication; SDMA covers waits, chunked copies, global timestamps, architecture-correct 32-bit fence signals, and one-doorbell publication.
- AMD PM4 queue finalization wraps the program's neutral submission as `Wait -> MemoryBarrier -> [Timestamp] -> Compute -> [Timestamp] -> Store` before command-buffer lowering. PMC diagnostic register streams remain backend-only inserts around lowered command segments.
- Packet-level AMD goldens cover every supported command, raw compute, mixed command order, dependency waits, release/acquire timestamp ordering, and final signal writes without GPU execution.
- `ExecutionPlan` lowers its level-preserving mixed prepared-op order into backend-neutral compute/copy `Submission` epochs. Buffer storage ranges derive cross-queue RAW/WAR/WAW waits; same-queue hazards rely on FIFO ordering.
- Plan-local compute, copy, and device timelines are monotonic across executions. First queue use waits the prior device epoch and a compute finalizer waits touched copy queues before advancing the device epoch.
- Normal and profiled execution consume neutral `Execute` commands. CPU execution is deterministic through this path, static compute-only plans retain graph replay, and output/buffer ownership remains with `ExecutionPlan`.
- Mock execution-plan tests cover independent compute/copy overlap, RAW, WAR, WAW, both compute/copy dependency directions, same-queue wait elision, finalization, and epoch rollover.
- Neutral `Submission` patch bindings classify immutable link addresses, invocation buffer GETADDR/scalar vars, and system-owned timeline/timestamp/scratch fields without exposing packet offsets to callers.
- Backend lowering produces deterministic link/runtime/system patch tables while emitting native packets. PM4 records wait/store/timestamp addresses plus program, kernarg, workgroup, and grid fields; SDMA records every chunk's adjusted source/destination plus wait/timestamp/store fields. Unsupported command/field combinations fail instead of guessing offsets from packet bytes.
- Immutable linked command buffers are cached by native template, exact lowering metadata, and link addresses. Reusable replay buffers scatter-patch runtime/system sites in place without rebuilding command streams or mutating cached static bytes.
- HCQ placeholder packing aliases scratch at offset zero using the maximum request and packs distinct kernarg blocks at 128-byte boundaries.
- `ClikeKernargLayout::pack_program` performs host GETADDR selection in canonical `ProgramInfo.globals` order and appends canonical positional i32 vars. Null tests cover packing, deterministic partitions, cache identity, changed replay values, and immutable link bytes; AMD packet tests cover repeated PM4 and chunked SDMA scatter replay.
- AMD graph capture now builds one backend-neutral compute `Submission`, lowers and links immutable AQL/PM4 packet bytes once, and retains replay buffers. Replays update canonical graph-owned kernargs from current buffer addresses and ProgramInfo vars, scatter-patch timeline/timestamp/scratch fields, and publish through the normal one-doorbell queue primitives without packet reconstruction.
- AQL graph completion is a trailing vendor-IB PM4 timeline store, matching direct and linked-plan AQL submission. PM4 graph waits, barriers, timestamps, and completion stores are ordinary neutral commands; live scratch VA/tmpring state is patched rather than triggering an IB rebuild. One memory barrier per captured graph matches tinygrad's `graph/hcq.py` device-queue head; per-dispatch coherence stays the narrow `acquire_mem` plus `CS_PARTIAL_FLUSH` already emitted by every dispatch, and FIFO order plus the AQL header BARRIER bit preserve every captured dependency edge. Cross-queue `opt_deps` wait narrowing remains deferred (review decision D7).
- The superseded graph-specific AQL packet capture, PM4 resident-IB builder/rebuilder, PM4 graph kernel/barrier records, and graph-only kernarg writer were deleted. Host-only AQL, PM4, and chunked SDMA replay tests change vars/runtime addresses/system fields across replays and verify linked static bytes remain unchanged.
- HCQ submissions now carry an explicit profiling request. AMD queue finalization owns timestamp allocation, PM4 timestamp insertion for both PM4 and AQL, timeline completion, and returned timestamp ownership; `AmdProgram` no longer allocates or brackets timestamp signals. Unprofiled submissions allocate no timestamp slot and emit no timestamp packets.
- Runtime profiling retains all dispatch records in one submission finalizer, performs one owner-local queue-timeline wait, harvests timestamps/counters in call order, and releases all handles together. The public `KernelProfile`/stage metadata API is unchanged. Null HCQ has a deterministic nanosecond clock and mixed compute/copy timestamp-order tests.
- AMD graphs retain a separate linked profiling variant while normal replay keeps the original command bytes and packet count. PM4 brackets each captured compute with queue timestamps directly; AQL carries the same timestamp commands in XCC0-predicated PM4 vendor IB runs. Profile replay waits only its graph owner and returns records in capture order.
- HCQ now owns typed device/compute/copy timeline points and submission wait/store finalizers. Each timeline carries dual signal generations, rolls at the 2^31 watermark, and reports exactly-once host resets when switching generations; runtime no longer advances three independent raw epoch counters or pairs values with addresses manually.
- AMD completion lifetime is unified under `SubmissionFinalizer`: owner-local synchronization and queue-wide draining retain exact monotonic memory-timeline points. The obsolete public countdown `arm`/`wait_done`/`is_done` APIs, per-path `HcqCompletion`, owner `my_newest`/`pm4_high`, and raw-signal in-flight FIFO are removed.
- AQL kernel and vendor packet completion handles remain zero. PM4-in-AQL and direct PM4 use literal monotonic timeline stores; SDMA uses `SDMA_OP_FENCE`, with `MTYPE(3)` outside gfx9. Staging SDMA copies wait through an exact submission finalizer and invoke whole-timeline draining only when a rollover reset is required.
- Graph normal replay patches a finalizer-owned timeline point. Profile replay allocates fresh timestamp slots, patches explicit timestamp addresses through HCQ system fields, and releases them with returned handles. PM4 and AQL replay patch timeline, scratch, and timestamp fields in one system patch pass.
- Lifecycle coverage includes shadow-signal rollover/reset consumption, submission-owned wait/store finalization, mixed compute/copy epochs, immutable graph replay repatching, signal-slot reuse, last-finalizer-drop release, and retained-clone/double-release prevention.
- CPU execution now consumes complete neutral submissions through `CpuQueueExecutor`: waits, barriers, prepared compute callbacks, host copies, timestamps, stores, and finalizers execute in vector order. Typed callback failures stop the submission before completion publication; null HCQ exposes the same compute-callback failure semantics for deterministic mixed-queue tests.

## Explicit AMD Packet Limits

- PM4 compute queues reject `Copy` and unresolved `Execute`; SDMA copy queues reject `Compute` and unresolved `Execute`. Queue migration must resolve `Execute` before packet lowering and schedule copies on SDMA.
- PM4 compute requires attached `AmdPm4Dispatch` state because shader resource registers and the raw entry address cannot be recovered from an AQL kernel-object GPU VA.
- Hardware wait packets compare 32-bit timeline values; values above `u32::MAX` are rejected. The existing timeline rollover must occur before that boundary.
- SDMA `MemoryBarrier` emits no packet, matching Tinygrad's compute-only barrier contract and SDMA FIFO ordering.
- Multi-XCC AQL non-dispatch commands use linked resident PM4-IB storage retained by the plan. Native AQL dispatch and SDMA packet formats remain unchanged; cross-engine waits/stores target coherent HCQ timeline resources and no unsupported architected AQL packet form is synthesized.
- AMD currently exposes no verified per-allocation peer-access query or cross-device SDMA submission context. Hardware mixed-device plans therefore conservatively use host staging through `Buffer::copy_from`; direct peer mode is enabled only for targets that explicitly report both required accessibility directions. No family-wide AMD peer access is inferred.

## Teardown Policy

- Panic unwind through `PoolQueue::drop`, `ActivatedQueueGuard::drop`, `AmdComputeQueue::close`, and `AmdCopyQueue::drop` quarantines the abandoned lane but no longer poisons the process-global `AmdDeviceCore` (review decision D3). Tinygrad latches its per-device error state only on a drain timeout or a reported fault, and an unwind reports nothing about the hardware. The HCQ-03/04 latch is correspondingly narrower: it now covers post-doorbell publication failures, failed drains, and faults.
- Quarantine is queue-local. `QueueInner::quarantined` decides whether the ring/GART/EOP backing is unmapped, so a queue whose KFD queue was never destroyed leaks its mappings regardless of whether the device happens to be poisoned or the process happens to be unwinding.
- Linked plans publish SDMA work against a plan-local timeline, so `AmdCopyQueue` retains those finalizers and drains them before teardown (VC6, narrow half). The wider fix — one per-device timeline signal as in tinygrad's `HCQCompiled` — would dissolve both this and the linked-publication guard nesting, and is scoped as its own change. `AmdCopyQueue::drop` also remains unreachable today because the installed `SignalPool` holds an `Arc<AmdDeviceCore>` while the core holds the pool; breaking that cycle is prerequisite work.
